### M2-01 — Legacy source classification (two-stage, one source = one count)

| Class | Persisted-evidence discriminator | Consequence for **fresh** preferential qualification |
| --- | --- | --- |
| **S0 — Structurally valid Completed source (gate, not proof)** | One same-tenant `Completed` `NEW_EXAMINATION` in `ROUTINE/URGENT/EMERGENCY`; matching patient/Doctor, one Visit bound to the actual `Waiting → In Examination` admission history revision, and a coherent `In Examination → Completed` history/time in Cairo. Check status/revision continuity, not only existence of a row or nonempty clinical narrative. | Advance to **S+** or **S?** assessment; S0 alone is **never** `examination_occurred=true`. |
| **S+ — Explicit positive examination evidence verified** | S0 **plus** an independently authenticated, explicit positive assertion tied to that exact source/completion and proven actor/time, from an approved trustworthy historical source. **No native `examination_occurred` evidence was found in `0018/0021/0022/0024` or inspected writers; external proof has not been reviewed.** | Candidate only after evidence admissibility, Doctor-ancestry and ordinary eligibility checks. **Classification order:** test structural S0 vs S! first, then S+ vs S? **within S0**; report S0 total separately from its disjoint S+/S? subdivision. ### M2-04 — Minimum Doctor-decision ancestry classifier

| Evidence path | Classification rule / precedence |
| --- | --- |
| `clinical_revisions` ordered by `(organization_id, visit_id, revision)` | Require a complete monotonic chain from Visit revision 1 through current `clinical_revision`, with each `old_values.followup_decision` matching the preceding `new_values` and the Visit's final JSON. `DECISION_DEFAULT` genuinely sets `DEFAULT`; `DECISION_EXCEPTION` must be read as its actual `OPTED_OUT` or finite justified `DEADLINE`, not treated as one generic exception. A complete chain with no decision (including an untouched revision-zero Visit) is **NO_DECISION**, not a fabricated Doctor DEFAULT; a broken chain is UNKNOWN. |
| `CORRECTION` vs `EXTENSION` | A `CORRECTION` changing effective `kind`, `deadline_date` or justification is a **semantic decision change**, even if the current B-10 lookup ignores it. An `EXTENSION` changing only claim-linked `extension_*` metadata, with matching `followup_extensions`/clinical-audit linkage, **does not change** the source decision; an `EXTENSION` that changes kind/deadline/opt-out semantics is **anomalous**, not silently accepted as an authorized new decision. |
| Actor attribution / missing chain | Correlate each relevant revision's actor ID/role/time, Visit Doctor, matching clinical audit, state and signed service provenance **where independently available**. `visits.doctor_staff_id`, a role label, `clinical_revisions.actor_staff_id` populated by `guard_visit()`, and caller-settable `app.staff_id` GUC are **not independent signed historical identity proof**. Missing/discontinuous, conflicting or unverifiable authorship = **ANCESTRY_UNKNOWN**, never a fabricated Doctor signature or permissive DEFAULT. Preserve original rows and revision numbers. |
| Doctor restriction precedence | Only a sufficiently verified **genuine Doctor** `OPTED_OUT`/`DEADLINE` can establish its corresponding restriction; preserve it until a later **verified Doctor** semantic change. It restricts prospective Receptionist decisions, exceptional dates and extensions; metadata-only EXTENSION neither overrides nor revokes it. If provenance is ambiguous, **deny new preferential mutation pending review** rather than assuming no restriction or inventing authorship. Confirmed frozen claims and permitted terminal results remain unaffected by later policy/restriction changes. |

### Legacy signed bodies and committed receipt compatibility — proposed minimum

The BFF signs the **SHA-256 of the exact raw HTTP body bytes** in its HMAC envelope (apps/web/auth/signing.ts:73–84; API identity/signing.py). This protects the transport and must not be replaced with the **different** receipt identity digest: typed, extra-forbid Pydantic input serialized with JSON mode, sorted keys, compact UTF-8 and **exclude_unset=True** (identity/contracts.py:110–128). Booking receipts use the typed-body SHA-256; Visit decision/extension receipts additionally prefix the 16 raw **UUID.bytes** of the route Visit ID before hashing (visits/eligibility.py:221,270). A freshly signed retry uses a fresh transport nonce while retaining the *same original idempotency key* and committed operation identity.

**Operation-specific, strict v1/v2 dispatch (conditional):** verify the **raw received body** with signed BFF HMAC/nonce and fresh live session, tenant/staff/operation authority before receipt processing. Reject malformed JSON and **duplicate keys**, unknown fields, hybrid families and partial v2 bodies; recognize only an unambiguous exact legacy v1 command or a strict v2 command by its version-distinguishing fields. Validate the selected family **once**, with its own extra-forbid typed schema; a failed v2 validation must never downgrade to v1, and a malformed v1 must never fall through to v2. Valid source-referencing/Visit-mutating v1 is **committed-receipt recovery only**, identified by original tenant + actual staff + operation + idempotency key and original canonical digest. No matching COMMITTED receipt means a sanitized incompatible-fresh-v1 denial; IN_PROGRESS/unknown outcomes are reconciled with the **same original key** and never independently committed as new v1 work. Return original result_revision/evidence, subject to fresh operation-specific resource/field visibility; no new qualification, pricing, source event, or claim is executed. Changed typed body against a committed key is **409 IDEMPOTENCY_CONFLICT**; different actor/tenant/operation, revoked grant and nonvisible record cannot recover it.

**Source-free ordinary booking overlap:** A `POST /v1/appointments` request with **no actual source reference or exceptional authorization** may have an identical valid v1 and v2 body shape. Treat that shared shape as a **common ordinary-booking family**, not as an ambiguous preferential legacy request: retain its original canonical typed-body digest (including absent vs explicit-null fields), checked PRICE/SCHEDULE/applicable CAPACITY/quote, active Patient/date/slot rules and authorized fresh Booked-only semantics.
