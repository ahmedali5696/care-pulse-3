# Wave 2 Data Model

Existing Phase 1 design aligned 2026-11-04, not executable DDL or amended acceptance. Technical proposals below await independent review (plan M1–M3). Sources: [spec.md](spec.md), master §§2/7/11.4 and Domain §§3–11. [Research](research.md) records choices; [transactions](contracts/transactions.md) records lock/atomicity boundaries. Logical new names are implementation design, not new product resources.

## Shared representation and security

- Reuse immutable application UUIDs and existing native Better Auth identity/session types. Clinical rows require non-null tenant identity, unique tenant/ID keys and tenant-qualified foreign keys; verify patient/Doctor/Appointment relationships, not just independent valid IDs. No clinical cascade deletion.
- Event/expiry/admission/completion instants are UTC `timestamptz`; Cairo service/deadline dates are `date`. Operational and clinical evidence separately record actual actor ID/role/tenant and at least second-precision time. Never derive service day by truncating UTC or move it at midnight.
- Server-incremented revisions and expected-revision checks apply inside locked writes. Preserve exact Appointment labels: Booked, Waiting, In Examination, Completed, Cancelled, No-show. Queue/claim/approval/review dispositions are not extra Appointment states.
- All new clinical tables use FORCE RLS read/write checks, non-owner NOBYPASSRLS runtime, no-context denial and no operator clinical grants. Protected Doctor content has stronger field/access guards than operational data. Only the migration role owns DDL.
- Use existing B-01 `protected_transaction`/`AuthorizedStaff`, which establish `app.staff_id` after live authorization. Doctor write/audit guards resolve that actual staff identity against current staff/clinic/Doctor linkage and security/reset-block conditions, following the existing `guard_clinical_audit` pattern. Do not trust an `app.role` string, request actor or fabricated old/new JSON. This is the existing trusted runtime credential boundary, not a claim that a malicious holder of that credential cannot forge a custom GUC.
- Connection-taking persistence primitives establish lock order before writes; deferred constraint checks inspect final current rows and do not acquire late upstream locks. Revoke update/delete and install immutable-evidence guards as appropriate. Operational receipts/outbox must not contain clinical narratives or protected before/after values.

### Policy/monetary compatibility

Initial prices remain null/unconfigured. New B-06 publication accepts/emits finite decimal strings; use a forward-only evolution of the existing PRICE validator to retain historical numeric/null versions while validating new string versions. Parse legacy JSON numbers from database text into Decimal, not binary floats. Retain old policy bytes/identities and references. Add representative old/new policy upgrade/read tests and keep D-04 seed defaults valid.

Nonnegative two-digit EGP bases/fixed discounts; finite percentage in [0,100]; required nonblank reason for FIXED/PERCENT, no reason/value for NONE except zero value. Both booking roles may discount standard or preferential bases under the same guards. Discretionary Free non-Urgent is a reasoned full discount, not an independent contradictory total. Snapshot `is_free` is derived from zero final net, including a configured zero preferential base with NONE; that configured base is neither unset nor a discretionary discount and needs no discount reason. Positive fixed reduction against zero fails; a valid percentage remains zero and needs its reason. No Free Urgent. Use adequate Decimal precision and one nonnegative final-net ROUND_HALF_UP; Urgent base and rounded net must exceed current standard base. Enablement requires valid general-calendar periods; subsequent calendar edits need no automatic toggle change or blanket ban, but confer no later intake eligibility when periods are missing. Future changes never reprice.

Spec CHK011 imposes no additional percentage fractional-digit cap within existing request-size safeguards. Reuse D-05's unconstrained NUMERIC `discount_value`, preserving the full accepted numeric value; money remains two-digit EGP, but PERCENT must not be quantized to that scale. Quotes, snapshot validation/persistence and serialization must round-trip that value without binary float or precision loss. Exact arithmetic must accommodate accepted coefficient and fractional scale before one final-net rounding; a fixed default precision is not a substitute. Preserve existing snapshot values and guards; verify US2.7's ordinary/high-precision examples and zero/100/invalid boundaries during B-06, not by changing historical snapshots or introducing a new storage representation.

Cutoff remains `{enabled:false, local_time:null}` initially. B-07 rejects enabling without an explicit valid Cairo-local HH:MM; it neither guesses a time for historical storage nor treats work-period end as cutoff. Stronger operational validation applies to new publication without rewriting old versions.

### Appointment and timed validation

Retain partial counted uniqueness `(organization_id,patient_id,service_date)` for Booked/Waiting/In Examination/Completed. Cancelled/No-show permit a distinct new ID; Completed blocks. Open has null endpoints and no time-derived cap. Timed requires both positive canonical instants, intended Cairo date and valid applicable periods/breaks/date rules; gap/fold input resolution is in [research §4](research.md#4-interval-capacity-and-cairo-time). Actual counted timed occupancy is transactionally checked against configured overlap capacity; an exclusion constraint alone cannot implement capacity above one.

Spec CHK001/003/021 answers govern new confirmation: reject past Cairo dates/passed starts today; use the one active clinic-wide mode and exact current manual/unsuppressed generated candidate endpoints. Preserve prior Open/timed records across mode/slot changes without retroactive candidate matching. Per the approved 2026-10-28 Product Owner decision, schedule date/work-period/break invalidation is blocking for future `Booked`/`Waiting` (even on Waiting-only dates), but does not retroactively invalidate `In Examination`/`Completed`; original dates, states and intervals are retained. Preview every affected slot/mode/duration/overlap change; count all four timed statuses in peak occupancy on relevant future dates, even with no `Booked` or change to overlap settings, and block a proposed effective limit below current peak, including disabling overlap with overlapping bookings. The effective limit is 1 with overlap OFF or saved examination capacity with overlap ON, not a separate setting. Price/schedule/source revisions and reviewed quote are comparison preconditions; stale new work fails, while committed receipt recovery retains the original snapshot. Clinic/day number uniqueness/non-reuse is not a gapless guarantee. Cutoff review shows prospective still-Booked reconciliation exposure; it does not introduce an interval boundary or change state.

Spec CHK002 explicitly excludes a maximum future booking horizon for Open/Exact-Time availability and new confirmation. No horizon column, setting, expiry or pre-materialized future slot series is added; evaluate the requested valid service date under current guards. Preferential Follow-up still enforces its authorized deadline and all ordinary guards. This changes neither retained service dates nor later-wave existing-ID workflows.

Spec CHK006 uses existing CAPACITY policy directly for enabled timed overlap, not a separately editable SCHEDULE booking limit or duplicate capacity field. Enabling requires configured Exact-Time slots and live authorized settings-actor confirmation of the current saved integer capacity >=2 and its revision. The confirmed value is a comparison precondition, not a capacity write; no additional numeric ceiling is approved. New booking reads/rechecks current saved capacity under policy locks. Preserve historical policy payloads and existing bookings; capacity-changing commands remain B-14, and booking does not consume or supply an admission confirmation.

Spec CHK007 anchors generation to each applicable working period's start, advancing in positive duration-sized steps. Keep only full intervals ending within that period; omit break intersections without restarting or shifting the grid, discard trailing remainders and then suppress intersections with valid manual slots. Derive candidates from the current schedule rather than persisting a second grid; existing confirmed intervals remain unchanged.

Spec CHK008 uses the existing weekly/date-keyed interval representation for weekly manual slots and explicit date-specific replacement sets. Preserve whether a date-specific set is configured: its presence replaces that date's entire weekly manual set; absence inherits the weekday's weekly set. This is manual-set selection, not a work-period override, union, inferred opening or generated-grid reset. Apply the resolved date/work/break/holiday guards before effective valid manual candidates suppress generated intersections. Reuse schedule versions/preview and preserve existing intervals.

Date snapshot immutable for active day; later policy does not silently reorder it. EMERGENCY does not own/advance MAIN cursor. |
| QueueEntry | Tenant/ID, QueueDay/Appointment/patient/Doctor, original date/lane, server arrival sequence and attestation actor/time, Routine rank when applicable, active/closed disposition, closure/attendance-history reference, revision. | Partial unique active tenant/Appointment; unique partition arrival sequence and valid active Routine ranks. | DoctorControl | Tenant/Doctor identity, synchronization revision and reference to current D-04 CAPACITY policy/relevant control revisions. | One shared row across every service date/lane, locked before queues. Existing CAPACITY policy remains authoritative for Pause/capacity; no independently editable duplicate settings or active-count cache. Initialize for existing/future tenants through the established narrow initialization pattern. |
| DoctorAdmissionConfirmation | Tenant/ID, issuer/Doctor/patient/target Appointment, original date/lane, issued/expires instants, captured Appointment/QueueDay/control/CAPACITY/authorization revisions, ISSUED/CONSUMED/REVOKED, consuming admission-history reference/time, revoke evidence. | Exact same-tenant/Doctor/patient target. Doctor-only issue/explicit revoke; unused valid confirmation consumed once with matching admission/history/queue closure. Expiry and stale invalidation derived; equality at expiry is unusable. Deferred checks on **both** Appointment and QueueEntry changes enforce final-state equivalence: Waiting has exactly one active entry matching tenant/Doctor/patient/original service date/lane; every non-Waiting record has zero. Check current final rows, not an earlier trigger NEW image. Unique-active alone cannot enforce existence or correct matching. Preserve inactive history instead of a date-qualified FK to the Appointment's mutable current service date.

Use the shared Doctor control lock and current D-05 `In Examination` Appointment count across all dates/lanes to enforce the capacity boundary in persistence simulations. Approval consumption references the immutable D-05 `Waiting → In Examination` admission-history revision; it does not require a Visit FK. Cursor may advance only with ordinary MAIN/Routine-head admission evidence, never Emergency/Urgent/Doctor exception, cancellation or reorder.

QueueDay creation must snapshot the effective policy for its original approved service date. Open attendance may create a dated partition without inferred hours/end time; an absent calendar leaves appropriate pending policy effectiveness rather than inventing an operating day. No creation happens from ordinary booking. Actual check-in/ordering/issue/revoke/Pause/admission commands remain B-12–15.

## D-08 — Source decisions, frozen claims and separate confirmed extensions

The following are logical contract records; exact physical mapping and old caller compatibility remain plan M2/M3 engineering review gates.

| --- | --- | --- |
| Follow-up source state and append-only decision evidence | Tenant/source Visit/Appointment/patient/Doctor, source_revision, DEFAULT/OPTED_OUT/DEADLINE, concrete deadline when applicable, reason, actual actor ID/role, server time, prior/new decision references and immutable before/after audit, effective policy revision. | All authorized staff; no decision/DEFAULT uses current policy without a Doctor author. | Retained FollowUpClaim | Unique preferential Appointment, tenant/patient/Doctor, Completed New Examination source Appointment/Visit and completion-local date; frozen effective FOLLOWUP policy/source revision, policy-derived or actual actor/role source evidence, any NEW-date exception, approved date/deadline, price-snapshot link; ACTIVE/RELEASED/CONSUMED, claim revision and terminal-history/time. | Same-tenant/patient/Doctor links; Routine FOLLOW_UP target, source Routine/Emergency/Urgent NEW_EXAMINATION. | NEW-booking exact-date authorization | Tenant/source, selected Cairo service date, current source/policy revisions, actual actor/role/time, reason and immutable audit reference linked to resulting claim/Appointment. | Doctor reason mandatory; Receptionist reason nullable. | Confirmed-extension evidence | Tenant/ID, exact ACTIVE claim/Appointment/source, prior effective authorization/date and specific later/non-shortening Cairo date/deadline, mandatory nonblank reason, actual actor/role/server time, expected source/Visit/policy/claim/Appointment revisions, prior-extension and immutable audit linkage. | Any authorized clinic staff, independent of Manager grant; append-only. Compare against latest effective authorization so a second extension cannot shorten a first. Recheck Doctor precedence, ACTIVE target and date bounds; increment claim authorization revision under lock. Never mutate original frozen source/price or Doctor clinical revision, move/reopen automatically or authorize another/new claim. |

Retain the smallest single-use ledger: unique source across ACTIVE or CONSUMED claims, excluding RELEASED history. Separate unique-active/unique-consumed indexes alone permit an invalid active reservation beside consumption. Preserve tenant-qualified FKs, FORCE RLS, narrow actual runtime grants and no operator access for all new evidence; append-only histories cannot be directly forged/updated/deleted by runtime clients.

**Revision contract:** operational source_revision is a distinct nonnegative concurrency token, advanced on source eligibility/provenance changes, never an alias for clinical_revision. No decision is a real policy-derived state, not missing Doctor authorization. Read/compare the reviewed token under locked source Appointment→Visit; decisions and booking compare expected_source_revision, source writes also compare expected_visit_revision, while confirmed extensions compare policy/source/Visit/claim/Appointment revisions. Here expected_visit_revision compares existing clinical_revision only to detect concurrent Doctor clinical changes; operational decisions/extensions never increment that clinical token. Doctor correction uses clinical_revision separately. Exact legacy token transition/receipt compatibility requires M3 review. Acquire patient/policy/day counter before Appointment→Visit→claim locks; new-claim policy computation belongs to B-10, not a dependency of D-08 persistence on B-06.

**Eligibility precedence:** genuine Doctor OPTED_OUT blocks new preferential actions; Doctor DEADLINE replaces the default and cannot be exceeded or modified by any Receptionist action. Only authenticated Doctor revision changes those restrictions. Otherwise a valid actual-actor source decision applies: effective OPTED_OUT denies, DEADLINE sets its specific inclusive date ≥ completion, absent/DEFAULT uses current Owner-configured FOLLOWUP day count (initially 7), including after release. Receptionists may amend prior Receptionist-authored decisions with immutable before/after; none of the three Receptionist paths may erase or route around Doctor precedence. A date exception cannot bypass an effective opt-out. Source edits never retroactively invalidate already frozen claims, but current Doctor restrictions constrain later Receptionist extensions/reschedules, including restrictions added after confirmation.

**Distinct dates:** intended date ≥ actual Cairo completion date, not original source service date or 168 hours. Source already Completed; day zero is eligible only if ordinary date/start/slot/archive/patient-day guards also pass. Original source service date equal to target remains counted and blocks a second Appointment; an older source service date finishing today does not by itself occupy today. New claim uses current policy/price; no released claim's extension or NEW-date authorization is inherited. A future B-18 move consults separately appended confirmed authorization and live Doctor precedence and rechecks ordinary booking guards without repricing.

**Projection boundary:** all-staff source/extension commands use explicit operational DTOs/evidence, never general Doctor content or raw clinical audit. Booking projections remain minimal; decision-control projection exposes only fields necessary to enter/revise operational decisions and recognize Doctor restriction denials (HTTP §6.1 proposal). Do not turn source IDs or tokens into general Visit read access.

A permitted nonqualifying/consumed fallback creates only New Examination with explicit ordinary-type/quote acknowledgment and discount reaffirmation. Busy ACTIVE source conflicts; explicitly hidden/missing source denies non-oracular 404 before fallback. A missing Doctor decision is not a fallback reason. Receipt replay reauthorizes first, never recalculates committed entitlement.

| --- | --- |
| Booked / Waiting / In Examination | ACTIVE, exactly one matching claim per preferential Appointment. |
| Cancelled / No-show | RELEASED with matching terminal history atomically, including Doctor exceptional In Examination cancellation retaining Visit. |

Check both Appointment→claim and claim→Appointment at commit, including source, classification, snapshot, terminal-history and completion evidence. Failed outcomes leave prior state intact; no source/policy edit retroactively invalidates a frozen claim. B-16/B-17/B-18/B-20 retain actual commands. No lifecycle PATCH/fixture endpoint is introduced. Published 0022 is immutable; amended guards/evidence require a separately authorized reviewed forward-only migration, populated predecessor/failure/privilege proof and exact-SHA CI. Earlier D-07/D-08/B-10 green CI proves only historical semantics.
