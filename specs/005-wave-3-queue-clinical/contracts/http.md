# Wave 3 HTTP Contracts

Phase 1 proposed contract, 2026-11-22; routes are design, not a claim of current support. Master §§2/8/11.1 and the approved field matrix govern. Reuse [Wave 1 protocol](../../002-wave-1-security-core/contracts/http-and-operator.md), [Wave 2 HTTP](../../003-wave-2-booking-scheduling/contracts/http.md), [F-01](../../../docs/f01-runtime-identity.md) and [transactions](transactions.md).

## Common boundary and wire behavior

Browser calls same-origin BFF `/api/*`; authenticated BFF validates live Better Auth session and Origin/CSRF, strips supplied identity headers and signs private `/v1/*`. Table paths omit these prefixes. API validates exact method/path/query/body and independently database-verified scope bound to actual tenant/staff/session/security revision, service login/backend/transaction and operation/resource. No direct browser/private-API privilege, caller actor/role/tenant override or shared-runtime fallback.

Use strict explicit snake_case schemas, duplicate-key rejection, UUIDs, Cairo `YYYY-MM-DD`, UTC RFC3339 instants, stable existing enums and EGP decimal strings. Server derives actor, status, lane/classification, rank, number, Visit, timestamps and amounts. Reject authority fields and unknown/mixed Doctor-owned inputs. Every row denies operator/foreign/disabled/revoked identity. Lists use existing bounded server pagination; no new numeric limit is selected.

Success uses established `{data, revision, event_id?}` with 201 for creation and 200 for read/update/recovery. Conflict uses 409 with existing symbolic codes; 401 invalid session, 403 forbidden operation/field, 404 non-visible resource, 422 invalid schema/value/transition, 503 required dependency/security policy unavailable. Reuse `{error:{code,message,request_id}}` and existing sanitization; disclose no SQL, PHI, clinical text or foreign-resource existence. New symbolic codes, if necessary, follow existing conventions and are technical names, not new product requirements.

Mutations use the shared Idempotency-Key/receipt contract, including previews and administrative controls. Key is scoped to tenant/actual actor/operation; the canonical command digest includes normalized target/day/preview identity from path/query as well as typed body. Preserve existing B-10 target-plus-body digests and historical compatibility. Changed command/target conflicts only after fresh authorization and field-safe resource visibility checks; the saved result must match requested target relationships before success. Each transport attempt needs a new signed nonce. Identical authorized recovery returns original committed result/revision without repeating effects; no return of old unsafe projection. Missing/unknown outcome is reconciled under the original key, not blindly replayed with a new key. See [transactions](transactions.md#receipts-failures-and-unknown-outcomes).

All applicable expected revisions are compared after ordered locks. A revision token never authorizes a resource. The field names below define planned command essentials; reuse existing upstream token types/names when consuming B-10 and do not collapse clinical/source/claim/authorization revisions into one generic version.

## Visit dispatch and field scope

Keep existing B-10 legacy/v2 source schemas, explicit current-policy/default/OPTED_OUT/DEADLINE evidence, genuine Doctor precedence and receipt recovery intact. The strict dispatcher chooses an operation family from validated disjoint fields; browser-supplied purpose never grants authority. BFF signing, API registration and DB route/body purpose validation must all bind the selected family. No mixed clinical/source atomic shortcut, forged clinical revision or widened VISIT_FOLLOWUP policy.

Doctor clinical PATCH allows examination/findings/diagnosis/medical_notes/treatment/tests/recommendation only, with clinical revision checks and immutable terminal correction audit. It cannot set completion, source decisions, claim state or actual actor. The source family cannot write those clinical fields. A Doctor recommendation does not book or confer entitlement. Ordinary staff completion accepts the positive assertion and operational revisions only.

General Visit/queue/history/error/receipt/outbox projections never return Doctor narrative, Doctor-authored source/exceptional reasons, or clinical before/after to Receptionists (preserving B-10's own-author operational source-decision reason only where that operation's field policy affirmatively permits it). Treating Doctor ID is linkage, not author attribution. Full one-patient export remains B-22's independent disclosure operation and grants no rights here; attachments remain B-21.

For both foreign-tenant and same-tenant wrong-resource requests, return `404` when the target or a required related Patient/Appointment/Visit is not visible in the operation-scoped projection, including mismatched resource linkage that cannot be disclosed. Return `403` for a forbidden operation/field regardless of any target's existence, and `409` only for a visible authorized target with conflicting state/revision. Apply this before receipt lookup/result disclosure so repeated keys cannot become a wrong-target existence oracle.

## Settings, timing and non-HTTP boundaries

Reuse B-07's configured `no_show_cutoff:{enabled,local_time}`; false/null remains default. Owner/live Manager can configure it under the existing allowlist; enabling requires a valid Cairo local time. For a selected `service_date`, B-20 resolves the enabled wall-clock time with **IANA `Africa/Cairo`** (not a fixed UTC offset): when ambiguous choose the **second** occurrence (`fold=1`); when nonexistent choose the **first valid local instant after the transition**. Compare authoritative server time against that resolved UTC instant and reject early or wrong-day application. This configured selected-day transition does **not** require the manual `overdue` predicate. It changes only still-Booked unarrived records for that day, atomically with any claim release/audit/outbox/receipt; same-day repeated/concurrent invocation must not duplicate effects. A partial failure or lost acknowledgment permits authorized reconciliation/retry for remaining eligible records, without a one-shot daily block. B-20 owns guarded cutoff selection/transitions, not a new public scheduler endpoint or settings control. B-25 owns background invocation and durable retries with distinct constrained worker operation/current tenant/date/policy authority; system-origin cutoff audit identifies system/worker actor kind and selected service date, never staff or Doctor authorship. These CHK037 semantics were expressly PO-approved on 2026-11-22.

`admission.doctor_confirmation_ttl` is deployment policy, not a new settings field. Absent/invalid value denies issue/use; consumption at the configured expiry denies. Production value awaits PO + Security/Operations, while separately labeled synthetic tests may proceed. No new policy/retention/transport/security number is chosen.

Before enabling each row, align its BFF route, API registration, DB route/purpose/resource/body/stage checks, read/write/receipt grants and evidence actions together. Current 0040-only or migration-role tests do not establish those operation contracts.
